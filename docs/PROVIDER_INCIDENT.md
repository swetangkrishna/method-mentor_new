# Provider incident template

This public template has not been submitted. The completed incident record and reproduction context remain in the private operator handoff.

For a recurring apparent false positive, prepare a private report containing:

- A concise description of the intended educational/research-methods use.
- A reviewed, non-sensitive synthetic reproduction and its necessary preceding context.
- Provider resource/deployment/model details and the approximate occurrence time.
- Sanitized status/category/phase metadata, with application references distinguished from provider request IDs.
- The observed impact and requested supported remedy, while preserving appropriate safety protection.

Do not include credentials, participant records, allocation seeds, private infrastructure addresses or unreviewed exports. A category label does not identify the exact triggering sentence or establish user wrongdoing. Do not fabricate or recover blocked model output.

Microsoft documents a Filters Feedback option in the playground and a support-ticket route, and advises excluding private or sensitive information: [Microsoft Learn: report content filtering feedback](https://learn.microsoft.com/en-us/azure/foundry-classic/openai/how-to/content-filters#report-content-filtering-feedback). Review the private draft before submitting.
